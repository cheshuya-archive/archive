# Аналитика сайта «Чешуя»

Публикуемая версия сайта находится в `dist/`: GitHub Pages загружает именно эту папку. Код аналитики подготовлен в отдельной ветке `feature/analytics-consent`; основная ветка и опубликованный сайт не меняются до отдельного разрешения.

## Подключение

- GA4: `G-4RV13D7DNW` уже указан в `dist/analytics.js`.
- Microsoft Clarity: Project ID бесплатного проекта получен и указан в `dist/analytics.js`.
- Cloudflare Web Analytics: beacon token проекта получен и указан в `dist/analytics.js`. На GitHub Pages используется ручная установка маячка после согласия посетителя.

Все три идентификатора теперь указаны. Перед публикацией нужно **отдельно согласовать** её с владельцем. Никакой платный тариф не нужен.

## Работа для посетителя

Плашка согласия плавно появляется через 3 секунды после входа и плавно уходит после выбора. До выбора «Разрешить» внешние скрипты не создаются. «Отклонить» блокирует все три системы. Ссылка «Конфиденциальность» находится под контактами в футере; на этой странице есть «Настройки аналитики», где можно изменить выбор или отозвать согласие. После отзыва страница перезагружается без аналитических скриптов. Согласие хранится только в текущем браузере.

Для исключения собственных посещений откройте любую страницу с `?preview=1` и подтвердите тестовый режим. Это нужно отдельно сделать на компьютере и телефоне. Режим сохраняется при переходах и перезагрузках; выключается в настройках аналитики или ссылкой с `?preview=0`.

Политика находится в `dist/privacy.html`. Её текст временный и должен быть проверен владельцем перед публикацией.

## События

`section_view`, `tab_open`, `project_open`, `gallery_open`, `gallery_progress` (25/50/75/100%), `image_expand`, `contact_click` отправляются в GA4; при подключении Clarity туда передаются также имена событий и теги раздела/проекта. Cloudflare Web Analytics получает только общую статистику посещений: произвольные события этот сервис не поддерживает. Для сравнения релизов передаётся `site_version` — короткий Git SHA, создаваемый при публикации.

## Локальная проверка без отправки данных

1. Запустить `node scripts/serve-local.mjs 3104` из корня проекта.
2. Запустить установленный Chrome с локальным DevTools-портом 9223 и отдельным временным профилем.
3. Выполнить `node scripts/test-analytics-local.mjs`. Тест блокирует домены аналитики до перехода на сайт и проверяет отказ, согласие, тестовый режим, отзыв, события и мобильную ширину.

Тесты не являются подтверждением приёма данных реальными аккаунтами: это станет возможным только после отдельной публикации с разрешения владельца.
